# ReelMind MVP 编写思路与实施计划

## 1. MVP 目标

本 MVP 的目标不是一次性完成 PRD 中的完整插件形态，而是先用一个独立网页产品验证核心价值：

> 用户是否愿意把知识视频导入 ReelMind，并使用 AI 摘要、知识点提取、思维导图，把“收藏的视频”转化为“可复习的知识资产”。

当前阶段优先做 Web 版，后续再改造成浏览器插件。这样可以避开早期插件权限、抖音精选 DOM 解析、浏览器商店审核等不确定性，先验证产品体验、AI 输出质量和用户留存。

## 2. 产品形态策略

### 2.1 第一阶段：独立 Web 应用

Web 版作为 MVP 主形态，提供一个完整但轻量的知识库工作台。

核心路径：

1. 用户注册/进入产品。
2. 用户手动添加知识视频：填写视频链接、标题、作者、收藏夹，并粘贴字幕或正文材料。
3. 系统生成结构化知识点、摘要和思维导图。
4. 用户在知识库中回看、编辑、导出内容。

Web 版暂不强依赖抖音精选页面自动解析。视频链接可以作为元数据保存，字幕来源先支持手动粘贴，后续再加入插件自动采集、浏览器剪贴板导入或服务端解析能力。

### 2.2 第二阶段：浏览器插件

插件不是重写产品，而是 Web 版能力的场景入口。

插件主要负责：

- 在抖音精选视频页识别视频标题、作者、链接、封面等元数据。
- 提供“一键收藏到 ReelMind”的入口。
- 尝试读取页面字幕；读取失败时引导用户到 Web 端补充字幕。
- 在视频页侧边栏展示已生成的摘要、知识点和导图入口。

后续插件应复用 Web 版的后端 API、数据模型、AI 生成能力和核心 UI 组件，避免形成两套产品。

## 3. MVP 范围

### 3.1 必做功能

| 模块 | MVP 内容 | 目的 |
| --- | --- | --- |
| 用户与本地会话 | 简单登录或开发期匿名用户 | 支撑用户数据隔离，降低早期复杂度 |
| 收藏夹管理 | 创建、重命名、删除收藏夹 | 支撑基础知识分类 |
| 视频收藏 | 手动添加视频链接、标题、作者、封面、备注、标签 | 建立知识库入口 |
| 字幕/文本导入 | 支持用户粘贴字幕或视频文字稿 | 绕开早期平台解析风险 |
| AI 知识提取 | 输出关键知识点、时间戳、重要程度 | 验证“看完即忘”的核心痛点解决能力 |
| AI 摘要 | 输出概述、章节摘要、核心结论 | 提升用户快速回顾效率 |
| 思维导图 | 基于 AI 结构化 JSON 渲染基础导图 | 验证差异化可视化价值 |
| 知识详情页 | 展示视频信息、知识点、摘要、导图 | 形成可回访的知识资产 |
| 基础导出 | 复制 Markdown 或导出 Markdown | 让用户把结果带到其他工具中 |

### 3.2 暂不做功能

| 功能 | 暂缓原因 |
| --- | --- |
| 讲解 HTML 动画 | 成本和生成质量不确定，MVP 先用摘要和导图验证价值 |
| 学习计划与复习提醒 | 需要一定收藏量后才有价值，先观察用户是否会持续导入和回访 |
| 知识关联推荐 | 冷启动数据不足，推荐质量难保证 |
| 自动解析抖音精选字幕 | 平台结构和合规边界不确定，放到插件阶段解决 |
| 支付订阅 | 先做额度和权益结构预留，等种子用户验证后再接支付 |
| 多平台适配 | MVP 只围绕“知识视频”抽象，不急于适配 B 站、YouTube 等平台 |

## 4. MVP 核心用户流程

### 4.1 首次使用流程

1. 用户进入 Web 应用。
2. 看到空知识库，引导添加第一个视频。
3. 用户输入视频链接、标题，选择或创建收藏夹。
4. 用户粘贴字幕或文字稿。
5. 点击“生成知识卡片”。
6. 系统生成知识点、摘要和导图。
7. 用户查看结果并复制/导出。

### 4.2 日常使用流程

1. 用户打开知识库。
2. 按收藏夹、标签或关键词查找视频。
3. 打开知识详情页。
4. 复习摘要、知识点和导图。
5. 编辑不准确的 AI 结果，或重新生成。

### 4.3 未来插件流程

1. 用户在抖音精选观看视频。
2. 点击插件按钮。
3. 插件自动带入视频元数据。
4. 如果能获取字幕，则直接提交生成；如果不能，则打开 Web 端补充字幕。
5. 生成结果回写到 Web 知识库，并可在插件侧边栏查看。

## 5. 页面规划

### 5.1 MVP 页面清单

| 页面 | 核心内容 |
| --- | --- |
| 知识库首页 | 视频列表、收藏夹筛选、搜索、添加视频入口 |
| 添加视频页/弹窗 | 视频链接、标题、作者、收藏夹、标签、备注、字幕粘贴 |
| 知识详情页 | 视频信息、处理状态、知识点、摘要、思维导图、导出操作 |
| 收藏夹管理 | 收藏夹列表、创建、重命名、删除 |
| 设置页 | AI 额度展示、模型配置占位、导出偏好 |

### 5.2 关键状态

每个核心页面需要覆盖以下状态：

- 空状态：还没有收藏视频、还没有收藏夹、还没有生成结果。
- 加载态：AI 生成中、导图渲染中。
- 成功态：结果生成并保存。
- 失败态：字幕为空、AI 超时、返回格式错误、网络失败。
- 编辑态：用户修改知识点、摘要或导图节点。

## 6. 数据模型建议

MVP 先保留 PRD 中完整模型的核心子集。

| 实体 | 必要字段 |
| --- | --- |
| User | id、email/nickname、plan_type、created_at |
| Folder | id、user_id、name、color、sort_order、created_at |
| Video | id、user_id、folder_id、platform、url、title、author、cover_url、transcript、duration_sec、status、created_at |
| KnowledgeCard | id、video_id、key_points、timestamps、created_at |
| Summary | id、video_id、overview、chapter_summaries、key_takeaways、status、created_at |
| MindMap | id、video_id、node_data、status、created_at |
| AiJob | id、user_id、video_id、job_type、status、input_hash、error_code、created_at、finished_at |

建议增加 `AiJob`，统一管理提取、摘要、导图生成任务，方便后续做异步队列、重试、额度统计和插件端状态同步。

## 7. 技术实现思路

### 7.1 前端

建议优先选择 Web 应用技术栈：

- React / Next.js：适合后续做 Web 端和插件 UI 组件复用。
- Tailwind CSS 或现有设计系统：快速搭建清晰的工具型界面。
- 思维导图库：优先使用成熟库，如 React Flow、Markmap、D3 tree 或 XMind 风格树图组件。

前端需要把“添加视频、查看知识详情、生成 AI 内容、导出 Markdown”做成稳定主流程。

### 7.2 后端

后端优先提供清晰 API，而不是一开始拆微服务。

建议模块：

- Auth：用户登录和会话。
- Video API：视频收藏、列表、详情、编辑。
- Folder API：收藏夹 CRUD。
- AI API：知识提取、摘要生成、导图 JSON 生成。
- Export API：Markdown 导出。

AI 生成建议先同步或短轮询实现；如果生成时间超过 20-30 秒，再升级为队列任务。

### 7.3 AI 输出约束

所有 AI 输出都应要求结构化 JSON，避免前端解析不稳定。

知识提取输出：

```json
{
  "key_points": [
    {
      "title": "知识点标题",
      "summary": "简短说明",
      "timestamp": "03:20",
      "importance": 4
    }
  ]
}
```

摘要输出：

```json
{
  "overview": "视频整体概述",
  "chapters": [
    {
      "title": "章节标题",
      "summary": "章节摘要",
      "start_time": "00:00"
    }
  ],
  "takeaways": ["核心结论 1", "核心结论 2"]
}
```

导图输出：

```json
{
  "root": {
    "title": "视频主题",
    "children": [
      {
        "title": "一级节点",
        "children": [
          {
            "title": "二级节点"
          }
        ]
      }
    ]
  }
}
```

## 8. 验证指标

MVP 阶段重点验证产品价值，不急于追求大规模增长。

| 指标 | 目标 |
| --- | --- |
| 首次添加视频完成率 | ≥ 60% |
| 添加视频后 AI 生成完成率 | ≥ 80% |
| AI 生成成功率 | ≥ 90% |
| 单次生成耗时 | 摘要/知识点 < 30 秒，导图 < 45 秒 |
| 生成结果复制或导出率 | ≥ 30% |
| 7 日内回访知识详情率 | ≥ 25% |
| 用户主动添加第 2 个视频比例 | ≥ 35% |
| AI 结果手动编辑率 | 记录即可，用于判断质量，不设硬目标 |

## 9. 迭代里程碑

### M0：产品骨架

- 建立 Web 应用基础框架。
- 完成知识库首页、添加视频、详情页静态 UI。
- 定义核心数据模型和 API 契约。

验收标准：可以手动创建收藏夹和视频，详情页能展示本地 mock 数据。

### M1：核心闭环

- 接入数据库。
- 完成收藏夹和视频 CRUD。
- 支持粘贴字幕。
- 接入 AI 知识点提取和摘要生成。
- 保存生成结果。

验收标准：用户可以从添加视频到生成知识点和摘要，形成完整可回访记录。

### M2：可视化与导出

- 接入思维导图生成。
- 渲染基础可交互导图。
- 支持复制/导出 Markdown。
- 补齐加载、失败、重试状态。

验收标准：每个视频详情页可以展示摘要、知识点、导图，并能导出复习材料。

### M3：种子用户验证

- 加入基础埋点。
- 加入 AI 用量统计。
- 增加反馈入口。
- 修复种子用户高频问题。

验收标准：可支持 20-50 个种子用户连续使用，并收集完整漏斗数据。

### M4：插件预研与改造

- 抽离 Web 端可复用 API 和 UI 组件。
- 设计插件 Manifest V3 结构。
- 验证抖音精选页面元数据识别。
- 做一键收藏到 Web 知识库的最小插件 Demo。

验收标准：插件能在视频页读取基础元数据，并把视频创建到 Web 端知识库。

## 10. 插件化预留原则

为了避免 Web MVP 后续难以改成插件，早期开发要遵守以下原则：

1. 业务能力全部走 API，不把核心逻辑写死在前端页面里。
2. 视频来源抽象为 `platform`，不要只写死 `douyin_jingxuan`。
3. 视频元数据和字幕导入分开，允许“先收藏，后补字幕”。
4. AI 任务独立建模，插件端只关心任务状态和结果。
5. UI 组件尽量拆成可嵌入的小组件，未来可放进插件 popup 或 side panel。
6. 不存储视频文件，不做下载能力，只处理用户主动提供的链接、元数据和字幕文本。

## 11. 近期开发顺序建议

1. 先完成 Web 信息架构和页面原型。
2. 再确定数据模型和 API。
3. 然后接入视频收藏、字幕粘贴、AI 摘要。
4. 接着做知识详情页和导图。
5. 最后补埋点、反馈、额度和插件预研。

这个顺序的好处是：每一步都能产生可演示的产品进展，并且始终围绕“用户是否愿意把视频变成知识资产”这个 MVP 核心假设推进。

## 12. 当前待确认问题

1. MVP 是否需要登录系统，还是先用匿名本地账号/开发账号验证？
2. 第一版 AI 模型供应商选哪一个，是否需要支持用户自己配置 API Key？
3. 字幕来源是否接受“用户手动粘贴”作为第一版主路径？
4. 思维导图第一版更重视美观导出，还是节点编辑能力？
5. 种子用户测试对象是谁，首批计划邀请多少人？
