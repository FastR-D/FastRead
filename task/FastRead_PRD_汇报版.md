# FastRead 产品需求说明

版本：2026-08-05

## 一、产品目标

FastRead 帮助用户真正读完一篇论文，而不是先做泛网页核验或生成零散笔记。

北极星链路：

```text
PDF / 论文 URL
-> 分页原文
-> 关键问题报告
-> 方法与贡献
-> 300 字个人总结
-> 带页码持续追问
```

## 二、目标用户

- 需要快速理解单篇论文的学生与研究者；
- 需要核对方法、贡献、实验与局限的工程人员；
- 需要保留页码依据并继续追问的读者。

## 三、P0 用户故事

### 导入

用户可以上传 PDF 或输入论文 URL。论文详情页包含 PDF 元数据时，系统继续抓取 PDF。没有可解析原文时失败关闭。

### 分页原文

系统逐页保存、搜索和显示原文，同时记录来源 URL、内容哈希、总页数、已解析页数、解析器与截断边界。

### 关键问题报告

报告至少回答研究问题、方法过程、主要贡献、实验/证据和局限。每个实质结论都应带可匹配的逐字引文与页码。

### 方法与贡献

方法按过程展示；贡献需要说明相对已有工作的增量。单篇论文只证明作者报告了什么，不能自动升级为领域共识。

### 300 字总结

用户总结与 AI 报告分开保存，最大 300 个字符。

### 持续追问

单篇论文问答优先检索分页原文。回答必须给出页码；没有支撑页面时明确拒绝补写。

## 四、可选证据审计

联网核验只在用户需要外部支持、反证、冲突、撤稿或信源风险判断时进入。它是报告证据层，不是产品主入口。

证据状态包括 `source_only`、`supported`、`refuted`、`mixed`、`insufficient`、`data_void` 和 `source_risk`。

## 五、验收标准

1. PDF 逐页文本可查看、搜索并保留页码。
2. 论文详情页 URL 能在存在 `citation_pdf_url` 时跟随 PDF。
3. 报告引用无法在指定页匹配时被丢弃。
4. 方法、贡献、实验与局限为稳定报告结构。
5. 个人总结不能超过 300 字。
6. 论文问答来源返回 `page_start` / `page_end`。
7. UI 将证据审计标记为“可选”“非主流程”。
8. 不把身份确认、原文定位、外部支持和实验复现混成一个结论。

## 六、后续优先级

- P1：限定会议语料的论文搜索；
- P2：从阅读报告生成带引用演示文稿；
- P2：团队资料库、权限、评论与审阅。
