# FastRead 产品需求说明

版本：2026-08-05

## 一、产品目标

FastRead 帮助用户真正读完一篇论文，而不是先做泛网页核验或生成零散笔记。

北极星链路：

```text
PDF / 论文 URL
-> 分页原文
-> 关键问题报告
-> 方法与贡献
-> 近邻论文 / 相关工作
-> 个人总结
-> 带页码持续追问
```

## 二、目标用户

- 需要快速理解单篇论文的学生与研究者；
- 需要核对方法、贡献、实验与局限的工程人员；
- 需要保留页码依据并继续追问的读者。

## 三、P0 用户故事

### 导入

用户可以上传 PDF 或输入论文 URL。论文详情页包含 PDF 元数据时，系统继续抓取 PDF。没有可解析原文时失败关闭。

### 分页原文

系统逐页保存、搜索和显示原文，同时记录来源 URL、内容哈希、总页数、已解析页数、解析器与截断边界。

### 关键问题报告

报告至少回答研究问题、方法过程、主要贡献、实验/证据和局限。每个实质结论都应带可匹配的逐字引文与页码。

### 方法与贡献

方法按过程展示；贡献需要说明相对已有工作的增量。单篇论文只证明作者报告了什么，不能自动升级为领域共识。

### 个人总结

用户总结与 AI 报告分开保存，可写短摘要，也可展开为完整阅读笔记；服务仅保留防止异常输入的安全上限。

### 持续追问

单篇论文问答优先检索分页原文。回答必须给出页码；没有支撑页面时明确拒绝补写。

## 四、近邻论文 / 相关工作

系统从已落到分页原文的研究问题、方法步骤与贡献生成检索锚点，在核心会议、arXiv 与 Scholar 元数据中发现近邻论文。结果展示相似锚点、重合词、相关度、来源与抓取时间；不判断论文主张真假，也不运行模型裁决。

## 五、验收标准

1. PDF 逐页文本可查看、搜索并保留页码。
2. 论文详情页 URL 能在存在 `citation_pdf_url` 时跟随 PDF。
3. 报告引用无法在指定页匹配时被丢弃。
4. 方法、贡献、实验与局限为稳定报告结构。
5. 个人总结支持短摘要与较长阅读笔记，并与 AI 报告独立保存。
6. 论文问答来源返回 `page_start` / `page_end`。
7. 近邻论文位于“方法与贡献”之后，单个提供方失败时保留明确状态。
8. 不把身份确认、原文定位、相似性发现和实验复现混成一个结论。

## 六、后续优先级

- P1：扩充核心会议元数据索引与近邻排序；
- P2：从阅读报告生成带引用演示文稿；
- P2：团队资料库、权限、评论与审阅。
