# Reel Mind 产品需求说明（技术汇报版）

## 1. 产品概述

Reel Mind 是一款面向知识型短视频的 AI 学习与事实核验工具。产品当前聚焦抖音精选知识视频，目标不是简单生成视频摘要，而是把短视频内容转化为可阅读、可复习、可追问、可核验的个人知识资产。

一句话定位：把知识视频变成带可信度核验的 AI 知识笔记。

本产品最大的创新点是“联网核验”能力：系统不仅总结视频内容，还会从笔记和转录文本中抽取可核验主张，识别高风险观点、数据陈述、因果判断和经验建议，并通过外部搜索源与 AI 判断辅助完成证据扫描，最终把“这条视频讲了什么”升级为“这些内容有多可信、哪些需要进一步核实、外部资料是否支持”。

## 2. 背景与问题

短视频已经成为用户获取知识的重要入口，但当前学习链路存在明显问题：

- 内容消费快，知识沉淀弱：用户收藏视频后很少回看，视频中的知识点无法被检索和复习。
- 信息质量不稳定：短视频常包含未经说明的数据、强因果判断、绝对化结论或高风险建议。
- 摘要工具只解决“看懂”，没有解决“可信”：普通 AI 总结容易把视频中的观点直接整理成笔记，缺少事实核验和风险提示。
- 用户缺少跨视频知识库：大量视频分散在平台收藏夹中，无法围绕多个视频做统一问答、主题复盘和证据追踪。

因此，Reel Mind 的核心价值不是“自动总结视频”，而是构建一条从内容提取到可信判断的学习闭环。

## 3. 产品目标

### 3.1 业务目标

- 帮助用户把知识视频沉淀为可复习的结构化笔记。
- 在 AI 总结结果上增加可信度核验层，降低错误信息被直接采信的风险。
- 建立个人视频知识库，支持按收藏、标签和问答方式复用历史内容。
- 验证“视频学习 + AI 总结 + 事实核验 + 知识库问答”的差异化产品方向。

### 3.2 技术目标

- 打通视频解析、音频转写、AI 笔记、知识卡片、主张抽取、联网核验的完整链路。
- 支持离线核验与联网核验两级机制：离线先识别风险，联网再补充外部证据。
- 支持可配置搜索源，包括 `brave`、`bing_academic`、`bing_cn`、`baidu`、`duckduckgo`。
- 支持 AI 辅助检索：使用当前配置模型提炼上下文、生成查询词、判断搜索结果是否支持或反驳主张。
- 将核验结果持久化到任务结果文件，供前端刷新、回看和重新核验。

## 4. 目标用户

### 4.1 学生与自学者

他们通过短视频学习课程技巧、考试经验、工具教程和科普内容。核心需求是快速抓住重点，并判断视频中的结论是否可靠。

### 4.2 职场知识工作者

他们关注行业观点、产品方法、效率工具、AI 工具和商业案例。核心需求是把碎片内容变成可复用资料，并能快速追问和查找来源。

### 4.3 内容整理者与知识博主

他们需要从大量视频中筛选观点、提炼素材、建立主题资料库。核心需求是判断内容价值、抽取可引用知识点，并识别哪些说法需要核实。

### 4.4 对信息质量敏感的用户

包括教师、培训人员、研究人员、产品经理等。他们不仅需要总结，还需要看到“证据是否充分、来源是否可信、是否存在反证”。

## 5. 使用场景

### 5.1 知识视频快速转笔记

用户粘贴抖音精选视频链接，选择模型后点击生成。系统完成视频解析、音频转写、AI 总结，输出 Markdown 笔记、思维导图和知识卡片。

### 5.2 视频观点可信度判断

系统从笔记和转录中抽取可核验主张，按数据陈述、因果判断、经验建议、高风险主题等类型分类。用户在知识卡片页看到核验分、风险等级、证据提示和联网核验按钮。

### 5.3 外部证据补充

用户点击“联网核验”后，系统对优先级最高的主张发起搜索。搜索结果经过相关性过滤、来源可信度判断和 AI 辅助判断后，形成“找到外部佐证”“存在反证”“证据不足”等结果。

### 5.4 收藏复习

用户生成笔记时可以填写收藏夹、标签和备注。生成后笔记进入“我的收藏”，支持刷新或重启后恢复。

### 5.5 跨视频知识库问答

用户积累多条视频笔记后，可以切换到知识库问答，围绕历史视频提问，例如“我之前收藏的视频里有哪些关于时间管理的建议”“哪些副业建议有较高风险”。

## 6. 核心功能范围

### 6.1 视频到笔记生成

- 输入视频链接，当前重点支持抖音精选。
- 解析视频标题、描述、标签、封面、视频 ID 等元信息。
- 下载音频并执行转写。
- 支持 `bcut`、`fast-whisper`、`Groq`、`MLX Whisper` 等转写方式。
- 支持在转写质量不足时合并平台元信息作为兜底上下文。
- 调用已配置大模型生成 Markdown 笔记。

### 6.2 多视图知识表达

- Markdown 笔记：用于详细阅读和内容复制。
- 思维导图：从专用 `## 思维导图` 章节渲染知识结构。
- 知识卡片：提取核心结论、知识要点、关键概念、操作步骤、风险提醒、行动清单、案例证据等。
- AI 问答：支持当前视频问答和知识库问答。

### 6.3 内容评分

系统为每条笔记生成三项评分：

- 信息密度：根据笔记长度、标题数量、列表项、转录长度等判断信息含量。
- 可信度：根据数字线索、来源词、证据词、风险主张和核验结论综合判断。
- 可执行性：根据步骤、方法、建议、清单、行动词等判断内容是否能落地。

### 6.4 联网核验

联网核验是当前产品的核心创新功能，包含以下子能力：

- 主张抽取：从 Markdown、转录文本中提取 14 到 180 字的可核验陈述。
- 主张分类：识别数据陈述、因果判断、经验建议、高风险主题、观点判断和事实陈述。
- 风险识别：针对医疗健康、金融投资、法律政策、公共安全等领域进行高风险提示。
- 优先级排序：优先核验高风险、含数字、含因果、含绝对化表达的主张。
- 搜索源链路：默认优先学术和国内搜索源，并支持 Brave Search API。
- 查询词生成：可使用 AI 结合视频上下文生成更适合搜索引擎的中英文查询词。
- 结果过滤：按文本覆盖率、关键词重合度、领域术语命中和低价值来源过滤搜索结果。
- 来源可信度判断：识别 `.gov`、`.edu`、`who.int`、`worldbank.org`、`stats.gov.cn`、`cnki.net`、`nature.com` 等权威域名或标题信号。
- AI 辅助判断：可调用配置模型判断搜索结果对主张是支持、反驳还是不确定。
- 结果落盘：核验后的主张、来源、评分和总体状态写回任务结果。

## 7. 系统架构

### 7.1 前端模块

前端位于 `reel-mind-frontend`，核心页面和组件包括：

- `HomePage`：视频链接输入、任务提交、笔记展示。
- `KnowledgeCardsView.tsx`：知识卡片、三项评分、可信度核验面板和联网核验入口。
- `MarkdownViewer.tsx`：Markdown、思维导图、知识卡片视图切换。
- `ChatPanel.tsx`：当前视频问答和知识库问答。
- `taskStore`：任务状态、转录、收藏信息、洞察数据和核验结果的前端状态结构。

### 7.2 后端模块

后端位于 `backend/app`，核心服务包括：

- `routers/note.py`：任务生成、任务状态、历史任务、收藏更新、联网核验接口。
- `services/note.py`：视频处理、转写、AI 笔记生成主流程。
- `services/insight_extractor.py`：知识卡片、内容评分、离线主张抽取和离线核验。
- `services/online_verifier.py`：联网搜索、查询生成、结果过滤、AI 判断和核验结果合并。
- `services/chat_service.py`：当前视频问答和跨视频知识库问答。
- `services/vector_store.py`：单任务向量索引，服务于当前视频问答。

### 7.3 数据持久化

- 任务结果保存在 `NOTE_OUTPUT_DIR`，默认目录为 `note_results`。
- 每条任务结果文件包含 Markdown、转录文本、视频元信息和 `insights`。
- 收藏夹、标签、备注等元数据存储在数据库任务记录中。
- 联网核验结果会更新到对应任务结果 JSON，刷新页面后仍可展示。

## 8. 核验链路技术设计

### 8.1 离线核验阶段

离线核验由 `build_insights` 触发，主要逻辑在 `insight_extractor.py`。

处理流程：

1. 清洗 Markdown 和转录文本。
2. 提取标题、列表项和句子。
3. 从文本中筛选可核验主张。
4. 对每条主张判断类型、风险等级和风险主题。
5. 根据是否含数字、因果、绝对化词、高风险领域、来源线索生成初始结论。
6. 生成 `verification.overall`、`claim_counts` 和 `claims`。

离线核验输出示例结构：

```json
{
  "external_check": false,
  "overall": {
    "status": "需核实",
    "score": 68,
    "summary": "抽取到 5 条关键主张，其中 2 条缺少外部证据或来源线索。",
    "note": "当前为离线核验，只判断可核验性、风险和文本内依据，不代表外部事实已证实。"
  },
  "claim_counts": {
    "total": 5,
    "needs_review": 2,
    "high_risk": 0,
    "medium_risk": 2
  },
  "claims": []
}
```

### 8.2 联网核验触发

前端在知识卡片视图点击“联网核验”，调用：

```text
POST /api/verify_task_online
```

请求参数：

```json
{
  "task_id": "任务 ID",
  "max_claims": 8,
  "model_name": "可选，核验使用模型",
  "provider_id": "可选，模型供应商"
}
```

后端处理逻辑：

1. 根据 `task_id` 读取任务结果文件。
2. 如果历史任务缺少 `insights`，即时补充生成。
3. 读取 `verification.claims`。
4. 取前端提交数量内的高优先级主张，后端最多处理 20 条。
5. 调用 `verify_claims_online` 执行联网核验。
6. 将新核验结果写回任务 JSON。
7. 返回更新后的 `insights` 给前端。

### 8.3 搜索源与兜底策略

根目录 `.env.example` 中默认配置：

```text
ONLINE_VERIFY_SEARCH_PROVIDER=brave
ONLINE_VERIFY_SEARCH_FALLBACK_PROVIDERS=bing_academic,bing_cn,baidu
BRAVE_SEARCH_API_KEY=your_brave_search_api_key
BRAVE_SEARCH_COUNTRY=CN
BRAVE_SEARCH_LANG=zh-hans
BRAVE_SEARCH_UI_LANG=zh-CN
```

搜索链路特性：

- 优先使用配置的主搜索源。
- 主搜索源失败时自动切换 fallback provider。
- 当结果不足、无权威来源或相关性偏低时，会触发国内补充搜索和质量补充搜索。
- 网络不可达、Brave API 鉴权失败、额度不足等情况会返回明确错误提示，不影响离线核验结果保留。

### 8.4 AI 辅助核验

当请求提供 `model_name` 和 `provider_id`，或系统能读取默认模型时，联网核验会启用 AI 辅助。

AI 辅助包含三步：

1. 上下文提炼：从视频标题、平台、标签、简介、笔记、转录中提炼主题、领域、关键术语和别名。
2. 查询词生成：把视频中的长观点改写为适合搜索的中英文查询词，保留实体、年份、术语和标准名称。
3. 结果判断：基于搜索结果标题、摘要、域名和视频上下文，判断主张为 `supported`、`refuted` 或 `uncertain`。

最终映射到用户可读结果：

- `AI 判断有外部佐证`
- `AI 判断存在反证`
- `AI 判断证据不足`
- `找到权威相关资料`
- `找到相关资料`
- `证据仍不足`
- `未找到外部证据`

### 8.5 核验评分更新

联网核验完成后，系统会统计：

- `online_checked`：已联网核验主张数。
- `online_supported`：找到外部佐证数量。
- `online_refuted`：发现反证数量。

总体状态会更新为：

- `联网核验完成`
- `仍需核实`
- `找到外部佐证`
- `保持离线核验`

核验分会在原始离线分基础上根据外部佐证数量调整，但不会把搜索结果等同于人工事实核查。前端也会展示说明：“联网核验基于搜索结果标题、摘要和来源域名做证据扫描，不等同于人工事实核查。”

## 9. 前端交互设计

### 9.1 入口

联网核验入口位于“知识卡片”视图中的“可信度核验”面板。

用户可见信息：

- 总体状态，如“需核实”“高风险”“找到外部佐证”。
- 核验分。
- 主张总数。
- 需核实数量。
- 高风险数量。
- 外部检索数量。
- 联网核验或重新联网核验按钮。

### 9.2 主张卡片

每条主张卡片展示：

- 主张文本。
- 风险等级：高风险、需核实、低风险。
- 主张类型：数据陈述、因果判断、经验建议等。
- 当前结论。
- 判断理由。
- 证据提示。
- 联网来源，最多展示前三条。
- 权威来源标记。

### 9.3 用户体验原则

- 默认先展示离线核验，保证无网络情况下仍有风险提示。
- 联网核验由用户主动触发，避免生成笔记时等待过长。
- 长时间请求设置较高超时，前端显示“核验中”。
- 核验失败时保留离线结果，并展示网络或搜索源错误。

```text

```

- `platform`
- `quality`


### 10.5 更新收藏信息

```text
POST /api/update_task_collection
```

更新收藏夹、标签和备注。

## 11. 数据结构

### 11.1 NoteInsights

```ts
interface NoteInsights {
  version: number

    title?: string
    transcript_type?: string
    transcript_chars?: number
    markdown_chars?: number
  }
  scores: {
    information_density: InsightScore

```

```ts
interface VerificationClaim {
  claim: string
  type: string
  type_label: string
  risk_level: 'low' | 'medium' | 'high'
  risk_topics: string[]
  verdict: string
  confidence: number
  reason: string
  evidence_hint: string
  priority?: number
  online?: {
    checked: boolean
    query: string

    }
    sources: Array<{

      snippet: string

    }>
  }
}
```

## 12. 差异化创新点

### 12.1 从“总结工具”升级为“可信知识工具”

普通视频总结产品只输出摘要，默认把视频内容整理成文本。Reel Mind 增加主张抽取和核验机制，告诉用户哪些内容可以暂时采纳，哪些内容需要查证。

### 12.2 离线核验与联网核验结合

离线核验保证基础可用性，联网核验提供外部证据增强。即使网络不可用，用户也能看到风险提示；网络可用时，系统进一步补证。

### 12.3 AI 搜索增强

系统不是简单把原句丢给搜索引擎，而是结合视频上下文改写查询词，处理视频中的简称、口语表达、术语缺失和中英文实体问题。

### 12.4 面向中文短视频场景的搜索链路

默认优先学术和国内搜索源，兼容 Brave API，并针对中文环境配置国家、语言和 UI 参数，提升中文短视频知识内容的检索可用性。

### 12.5 证据透明

前端不是只给一个分数，而是展示每条主张、风险等级、判断理由、搜索 query、来源标题、域名和摘要，便于用户继续人工确认。

### 12.6 知识库化复用

每次核验后的笔记会沉淀到历史任务中，和收藏、标签、知识卡片、AI 问答结合，形成可持续增长的视频知识库。

## 13. 评价指标

### 13.1 生成链路指标

- 视频解析成功率。
- 音频转写成功率。
- 笔记生成成功率。
- 从提交到生成完成的平均耗时。

### 13.2 核验链路指标

- 可核验主张抽取数量。
- 高风险主张识别准确率。
- 联网核验成功率。
- 平均每条主张返回有效来源数量。
- 权威来源命中率。
- `supported`、`refuted`、`uncertain` 分布。
- 用户点击重新核验的比例。

### 13.3 学习价值指标

- 用户是否能通过知识卡片快速复述视频结论。
- 用户是否能通过核验面板识别需要进一步查证的内容。
- 历史笔记回看率。
- 知识库问答命中率。
- 收藏夹和标签使用率。

## 14. 风险与边界

### 14.1 产品边界

- 联网核验不是人工事实核查，只是基于搜索结果标题、摘要、来源域名和 AI 判断做证据扫描。
- 搜索结果相关不等于主张被完全证实。
- 权威来源命中不代表视频表述细节完全正确。
- 高风险领域仍应提示用户查阅官方文件、专业机构或原始报告。

### 14.2 技术风险

- 搜索引擎页面结构变化会影响解析。
- Brave Search API 需要配置 Key，且可能受额度和网络影响。
- Docker、代理、DNS 和跨境网络会影响联网核验可用性。
- AI 判断可能受搜索结果质量和模型能力影响。
- 当前知识库问答仍是 MVP，需要进一步升级全局向量索引。

### 14.3 内容风险

- 视频本身可能只有标题和元数据，缺少完整转录。
- ASR 可能识别错误，影响主张抽取。
- 短视频常含夸张表达，系统需要持续优化绝对化表述和营销话术识别。

## 15. 后续规划

### 15.1 短期优化

- 在核验面板中展示搜索 query 和搜索源链路。
- 支持按主张单独重新核验。
- 增加“人工标记为可信/不可信/待查”。
- 为联网核验结果增加导出能力。
- 在生成任务结束后可选自动核验高风险主张。

### 15.2 中期优化

- 建立全局向量索引，支持按收藏夹、标签和时间范围做知识库问答。
- 增强权威来源白名单和低价值来源黑名单。
- 支持更多平台的视频解析和字幕预取。
- 增加引用溯源，将核验来源与笔记中的具体句子绑定。

### 15.3 长期方向

- 构建个人可信知识库。
- 支持团队知识审核和共享。
- 支持课程、报告、长视频和播客等多源内容。
- 形成“内容提取 - 证据核验 - 知识沉淀 - 复习问答”的完整学习基础设施。
